# Pipeline Data Dictionary

This document outlines the schema, origins, and transformation methodologies for the data tables generated by the `exchange_analysis` pipeline. Tables are categorized by their logical table names (passed to the I/O handler).

---

## 1. Raw Data Tables
These tables contain the direct, unpatched arrays retrieved from external APIs prior to any mathematical manipulation.

### `raw_generation` / `raw_load`
| Column / Field | Origin Data Source | Transformation & Extraction Logic |
| :--- | :--- | :--- |
| **`[Generation Type]`** | ENTSO-E API / BMRS (for GB) | Extracted directly from the source API. For GB, 30-minute JSON arrays are parsed and grouped by `psrType`. |
| **`Actual Load` / `Load`**| ENTSO-E API / BMRS (for GB) | Extracted directly from the source API. |

### `raw_commercial_flows` / `raw_commercial_flows_da` / `raw_physical_flows`
| Column / Field | Origin Data Source | Transformation & Extraction Logic |
| :--- | :--- | :--- |
| **`[bz]_[n]`** | ENTSO-E API | Outward flow queried using `country_code_from=bz` and `country_code_to=n`. |
| **`[n]_[bz]`** | ENTSO-E API | Inward flow queried using `country_code_from=n` and `country_code_to=bz`. |

### `raw_market_price_dayahead` / `raw_net_positions_dayahead`
| Column / Field | Origin Data Source | Transformation & Extraction Logic |
| :--- | :--- | :--- |
| **`Value`** | ENTSO-E API | Queried directly. **Transformation:** For Italian (IT) bidding zones in the year 2025, Net Positions are multiplied by `-1` to correct a systemic ENTSO-E sign convention error. Resampled to 1h averages. |

---

## 2. Processed & Synchronized Tables
These tables represent the "Clean Data Layer." The origin for all data here is the **Raw Data Tables**, which are then heavily transformed.

### `processed_generation`
| Column / Field | Origin | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`[Generation Type]`** | `raw_generation` | **1.** Resampled to 1h means. **2.** Gaps imputed (`fill_gaps_wrapper`). **3.** Any negative values (parasitic load) are clipped to `0.0` to preserve fraction integrity. |
| **`Storage Charge`** | `raw_generation` | **Calculated:** The absolute sum of all *negative* values isolated from the `"Hydro Pumped Storage"` and `"Energy storage"` columns. |
| **`Storage Discharge`** | `raw_generation` | **Calculated:** The sum of all *positive* values isolated from the `"Hydro Pumped Storage"` and `"Energy storage"` columns. |
| **`Generation`** | Internal | **Calculated:** The sum of all active generation components (strictly excluding the storage columns). |
| **`Total Generation`** | Internal | **Calculated:** `Generation` + `Storage Discharge`. |
| **`Demand`** | `raw_load` | **1.** Resampled to 1h means. **2.** Gaps imputed. |
| **`Total Load`** | Internal | **Calculated:** `Demand` + `Storage Charge`. |
| **`Net Export`** | Internal | **Calculated:** `Total Generation` - `Total Load`. |
| **`gap_filling_method`**| Pipeline Logic | Tracks imputation methods applied. Appends `CLIPPED_NEGATIVE` if the non-negativity constraint was triggered. |

### `processed_commercial_flows` / `processed_physical_flows`
| Column / Field | Origin | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`[bz]_[n]`** / **`[n]_[bz]`**| `raw_*_flows` | **1.** Resampled to 1h means. **2.** Gaps imputed. **3. Symmetry Enforced:** Resolves conflicting neighbor reports using `balance_flows_symmetry`. If one zone reports `0` and the other `>0`, the non-zero value overrides. If both report `>0`, a reliability index (based on zero-anomaly audit files) determines the trusted source. |
| **`[bz]_[n]_net_export`** | Internal | **Calculated:** Cleaned `[bz]_[n]` minus Cleaned `[n]_[bz]`. |
| **`Net Export`** | Internal | **Calculated:** The sum of all individual `[bz]_[n]_net_export` columns. |

## 3. Hourly Analysis & Decomposition Tables
These tables contain the mathematically derived origin of imported electricity. The **Origin** for all data here is the `processed_generation` and `processed_*_flows` tables.

### Level 1: Source Zone Breakdown (`*_bz`)
| Table / Suffix | Origin Methodology | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`analysis_cft_total_bz`** | `processed_commercial_flows` | **Passthrough:** Maps the absolute bilateral scheduled imports from neighbor `[n]` directly. |
| **`tracing_direct_coupling_bz`**| `processed_physical_flows` & `processed_generation` | **Matrix Inversion:** Constructs a topology matrix $A$ and absolute nodal generation vector $G_{in}$. Calculates the tracing matrix $q = A^{-1} \cdot G_{in}$. (Singularities on the diagonal are patched with `1.0`). |
| **`tracing_agg_coupling_bz`** | `processed_physical_flows` & `processed_generation` | **Matrix Inversion:** Constructs a topology matrix $A$ and nodal net-export vector $P_{in}$. Calculates the tracing matrix $q = A^{-1} \cdot P_{in}$. |
| **`pool_physical_net_pos_bz`** | `processed_physical_flows` | **Copper Plate Pooling:** Apportions a zone's total imports proportionally based on the system-wide pool of net exporters, ignoring exact grid topology. |

### Level 2 & 3: Granular & Technology Aggregation (`*_type_bz`, `*_type`)
| Table / Suffix | Origin Methodology | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`*_type_bz`** (e.g., `FR_Nuclear`) | Level 1 Data + `processed_generation` | **Decomposition:** The hourly imported volume from zone `n` (calculated in Level 1) is multiplied by zone `n`'s internal generation mix fraction for that specific `[Type]` at that exact hour. |
| **`*_type`** (e.g., `Nuclear`) | `*_type_bz` | **Aggregation:** Sums all incoming flows of a specific technology type across *all* source zones into a single column. |

### Level 4: Category Aggregation (`*_agg`)
| Table / Suffix | Origin Methodology | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`*_agg`** (e.g., `Renewable`) | `*_type` | **Mapping:** Sums specific technology flows (e.g., `Wind Onshore`, `Solar`) into broader macro-categories defined by the pipeline's internal `agg_map`. |

---

## 4. Post-Processed Annual Totals (`annual_*`)
These tables aggregate the high-granularity MW arrays into annualized Terawatt-hours (TWh) to allow for direct macro-comparison of the different accounting methodologies.

| Structure / Axis | Origin | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **Rows (Index)** | All Level 3 Analysis Tables | Represents the specific Bidding Zone (`FR`), Technology Type (`Nuclear`), or Category (`Renewable`). |
| **Columns (Values)**| All Level 3 Analysis Tables | Represents the applied tracking methodology (e.g., `CFT`, `AC Flow Tracing`, `Pooled Net Phys.`). **Transformation:** The 8760 hourly MW rows for the year are summed, and then divided by `1e6` to convert the absolute value to TWh. |
