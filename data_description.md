# Pipeline Data Dictionary

This document outlines the schema, origins, and transformation methodologies for the data tables generated by the `exchange_analysis` pipeline. Tables are categorized by their logical table names (passed to the I/O handler). 

*Note: All tables processed through the pipeline's `DataIO` handler automatically receive standardized metadata columns (`bidding_zone` and a temporal vintage stamp) to ensure robust database schema adherence.*

---

## 1. Raw Data Tables
These tables contain the direct, unpatched arrays retrieved from external APIs prior to any mathematical manipulation.

### `raw_generation` / `raw_load`
| Column / Field | Origin Data Source | Transformation & Extraction Logic |
| :--- | :--- | :--- |
| **`[Generation Type]`** | ENTSO-E API / BMRS (for GB) | Extracted directly from the source API. For GB, 30-minute JSON arrays are parsed and grouped by `psrType`. |
| **`Actual Load` / `Load`**| ENTSO-E API / BMRS (for GB) | Extracted directly from the source API. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO`. The target geographic zone (e.g., `DE_LU`, `FR`). |
| **`download_timestamp`** | Pipeline IO | The exact UTC datetime of the API extraction (Format: `YYYY-MM-DD HH:MM:SS UTC`). |

### `raw_commercial_flows` / `raw_commercial_flows_da` / `raw_physical_flows`
| Column / Field | Origin Data Source | Transformation & Extraction Logic |
| :--- | :--- | :--- |
| **`[bz]_[n]`** | ENTSO-E API | Outward flow queried using `country_code_from=bz` and `country_code_to=n`. |
| **`[n]_[bz]`** | ENTSO-E API | Inward flow queried using `country_code_from=n` and `country_code_to=bz`. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO`. |
| **`download_timestamp`** | Pipeline IO | The exact UTC datetime of the API extraction. |

### `raw_market_price_dayahead` / `raw_net_positions_dayahead`
| Column / Field | Origin Data Source | Transformation & Extraction Logic |
| :--- | :--- | :--- |
| **`Value`** | ENTSO-E API | Queried directly. **Transformation:** IT net positions for 2025 are multiplied by `-1` to correct an ENTSO-E sign convention error. Resampled to 1h averages. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO`. |
| **`download_timestamp`** | Pipeline IO | The exact UTC datetime of the API extraction. |

## 2. Processed & Synchronized Tables
These tables represent the "Clean Data Layer." The origin for all data here is the **Raw Data Tables**, which are then heavily transformed. 

### `processed_generation`
| Column / Field | Origin | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`[Generation Type]`** | `raw_generation` | **1.** Resampled to 1h means. **2.** Gaps imputed. **3.** Negative values clipped to `0.0`. |
| **`Storage Charge`** | `raw_generation` | **Calculated:** The absolute sum of *negative* values from `"Hydro Pumped Storage"` & `"Energy storage"`. |
| **`Storage Discharge`** | `raw_generation` | **Calculated:** The sum of *positive* values from `"Hydro Pumped Storage"` & `"Energy storage"`. |
| **`Generation`** | Internal | **Calculated:** The sum of all active generation components (excluding storage columns). |
| **`Total Generation`** | Internal | **Calculated:** `Generation` + `Storage Discharge`. |
| **`Demand`** | `raw_load` | **1.** Resampled to 1h means. **2.** Gaps imputed. |
| **`Total Load`** | Internal | **Calculated:** `Demand` + `Storage Charge`. |
| **`Net Export`** | Internal | **Calculated:** `Total Generation` - `Total Load`. |
| **`gap_filling_method`**| Pipeline Logic | Tracks imputation methods applied and any `CLIPPED_NEGATIVE` constraints. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO`. |
| **`source_download_date`**| Pipeline IO | Synchronized global vintage date (`YYYY-MM-DD`) representing the origin timestamp of the underlying raw data used for this processing batch. |

### `processed_commercial_flows` / `processed_physical_flows`
| Column / Field | Origin | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`[bz]_[n]`** / **`[n]_[bz]`**| `raw_*_flows` | **1.** Resampled (1h). **2.** Gaps imputed. **3. Symmetry Enforced:** Resolves reporting conflicts between neighbors using a trust-hierarchy index. |
| **`[bz]_[n]_net_export`** | Internal | **Calculated:** Cleaned `[bz]_[n]` minus Cleaned `[n]_[bz]`. |
| **`Net Export`** | Internal | **Calculated:** The sum of all individual `[bz]_[n]_net_export` columns. |
| **`gap_filling_method`**| Pipeline Logic | Tracks imputation and symmetry conflict resolutions. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO`. |
| **`source_download_date`**| Pipeline IO | Synchronized global vintage date (`YYYY-MM-DD`). |

## 3. Hourly Analysis & Decomposition Tables
These tables contain the mathematically derived origin of imported electricity. The **Origin** for all data here is the `processed_generation` and `processed_*_flows` tables.

### Level 1: Source Zone Breakdown (`*_bz`)
| Table / Suffix | Origin Methodology | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`analysis_cft_total_bz`** | `processed_commercial_flows` | **Passthrough:** Maps the absolute bilateral scheduled imports from neighbor `[n]`. |
| **`tracing_direct_coupling_bz`**| `processed_physical_flows` & `processed_generation` | **Matrix Inversion:** Constructs a topology matrix $A$ and absolute nodal generation vector $G_{in}$. Calculates the tracing matrix $q = A^{-1} \cdot G_{in}$. |
| **`tracing_agg_coupling_bz`** | `processed_physical_flows` & `processed_generation` | **Matrix Inversion:** Constructs a topology matrix $A$ and nodal net-export vector $P_{in}$. Calculates the tracing matrix $q = A^{-1} \cdot P_{in}$. |
| **`pool_physical_net_pos_bz`** | `processed_physical_flows` | **Copper Plate Pooling:** Apportions imports proportionally based on the system-wide pool of net exporters. |
| **`gap_filling_method`**| Pipeline Logic | Exists if gaps in upstream analysis required localized patching. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO`. |
| **`source_download_date`**| Pipeline IO | Synchronized global vintage date (`YYYY-MM-DD`) tracing back to the raw execution batch. |

### Level 2 & 3: Granular & Technology Aggregation (`*_type_bz`, `*_type`)
| Table / Suffix | Origin Methodology | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`*_type_bz`** (e.g., `FR_Nuclear`) | Level 1 Data + `processed_generation` | **Decomposition:** The imported volume from zone `n` (Level 1) multiplied by zone `n`'s internal generation mix fraction for `[Type]`. |
| **`*_type`** (e.g., `Nuclear`) | `*_type_bz` | **Aggregation:** Sums all incoming flows of a specific technology type across *all* source zones into a single column. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO`. |
| **`source_download_date`**| Pipeline IO | Synchronized global vintage date (`YYYY-MM-DD`). |

### Level 4: Category Aggregation (`*_agg`)
| Table / Suffix | Origin Methodology | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **`*_agg`** (e.g., `Renewable`) | `*_type` | **Mapping:** Sums specific technology flows (e.g., `Wind Onshore`, `Solar`) into broader macro-categories defined by `agg_map`. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO`. |
| **`source_download_date`**| Pipeline IO | Synchronized global vintage date (`YYYY-MM-DD`). |

## 4. Post-Processed Annual Totals (`annual_*`)
These tables aggregate the high-granularity MW arrays into annualized Terawatt-hours (TWh) for macro-comparisons.

| Structure / Axis | Origin | Transformation & Calculation Logic |
| :--- | :--- | :--- |
| **Rows (Index)** | All Level 3 Analysis Tables | Represents the specific Bidding Zone (`FR`), Technology Type (`Nuclear`), or Category (`Renewable`). |
| **Columns (Values)**| All Level 3 Analysis Tables | Represents the applied tracking methodology (e.g., `CFT`, `AC Flow Tracing`). **Transformation:** The 8760 hourly MW rows for the year are summed and divided by `1e6` to convert to TWh. |
| **`bidding_zone`** | Pipeline IO | Injected automatically by `DataIO` post-transposition. |
| **`source_download_date`**| Pipeline IO | Synchronized global vintage date (`YYYY-MM-DD`). |
